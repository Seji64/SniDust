DnsDist · Nginx · DoH · DoT · UDP

SmartDNS proxy to hide your geo-location

SniDust proxies your DNS requests and spoofs your origin IP, so geo-restricted services (Zattoo, Netflix, SRF.ch, Yallo, Hulu, Amazon Prime, …) see the IP of your server instead of yours.

▸ Quick start ★ GitHub ghcr.io/seji64/snidust

How it works

1 · Access control

Only clients on the ACL may use the proxy. IPs and DynDNS domains from ALLOWED_CLIENTS are resolved to IPs and written to /etc/dnsdist/allowedClients.acl; a cron re-resolves DynDNS names every 15 min.

2 · Blocklist match

Queries whose suffix matches one of the 11 lists in /etc/snidust/domains.d (55 entries) are tagged; everything else is passed through untouched.

3 · Origin rewrite

Tagged queries are answered by SpoofAction(EXTERNAL_IP): the resolver is told the query came from the server, so the service serves its ungeo-restricted answer set.

Quick start

  • Find your client IP
    curl https://ifconfig.co

    Run this on the device that will use the proxy. DynDNS domains work as well.

  • Find your server IP
    curl https://ifconfig.co

    Run this on the VPS that hosts SniDust. This is the IP that gets spoofed.

  • Start the image
    docker run -d \
  --name snidust \
  -e ALLOWED_CLIENTS="127.0.0.1, 10.111.123.7, myDynDNSDomain.no-ip.com" \
  -e EXTERNAL_IP=10.111.123.8 \
  -p 443:8443 -p 80:8080 -p 53:5300/udp \
  ghcr.io/seji64/snidust:latest

    Prebuilt for linux/amd64, linux/arm64 and linux/arm/v7 — no local build needed.

  • Check the log
    docker logs snidust

    You should see the upstreams (dns.google, cloudflare-dns) marked up and the ACL loaded.

  • Point your device at the server
    sudo resolvctl set nameservers 10.111.123.8   # macOS
# or set DoH/DoT manually: https://10.111.123.8/dns-query

    Set the DNS server of the device (or the whole network) to the public IP of your server. Geo-location hidden.

    • Docker Compose

    version: '3.3'
services:
    snidust:
        container_name: snidust
        image: 'ghcr.io/seji64/snidust:latest'
        environment:
            - TZ=Europe/Berlin
            - 'ALLOWED_CLIENTS=127.0.0.1, 10.111.123.7, myDynDNSDomain.no-ip.com'
            - 'EXTERNAL_IP=10.111.123.8'
            - SPOOF_ALL_DOMAINS=false
            # - 'DYNDNS_CRON_SCHEDULE=*/1 * * * *'
        ports:
            - 443:8443
            - 80:8080
            - 53:5300/udp

    Ports

    PortProtocolPurpose
    5300/udpDNSClassic DNS endpoint — map to 53:5300/udp.
    8080/tcpDoH (plain)Nginx reverse proxy for DNS-over-HTTPS, map to 80:8080.
    8443/tcpDoH / DoT (TLS)Nginx stream module with ssl_preread, map to 443:8443.
    8530/tcpDoH / DoT (TLS)Native dnsdist TLS endpoint, only with DNSDIST_ENABLE_DOT=true.
    8083/tcpHTTPdnsdist web interface, bound to 127.0.0.1; needs DNSDIST_ENABLE_WEBSERVER=true and -p 8083:8083.

    Configuration

    Core settings

    VariableDefaultDescription
    ALLOWED_CLIENTS127.0.0.1Comma-separated IPs or DynDNS domains allowed to use the proxy.
    ALLOWED_CLIENTS_FILE(empty)Path to an ACL file; allows reloading without a restart.
    EXTERNAL_IP(empty)Public server IP used for spoofing.
    SPOOF_ALL_DOMAINSfalseSpoof every query, regardless of the blocklists (not recommended).
    INSTALL_DEFAULT_DOMAINStrueInstall the domain lists shipped in the repo.
    DYNDNS_CRON_SCHEDULE*/15 * * * *Cron schedule for re-resolving DynDNS domains.

    Advanced setups

    DNS over TLS (DoT)

    See docker-compose.dot.yml and docker-compose.acme.sh-dot.yml in the repo for a self-signed or an ACME (real certificate) setup.

    Custom upstreams

    Create 99-customUpstream.conf with newServer({address="…", pool="customUpstream"}), mount it into /etc/dnsdist/conf.d/ and set DNSDIST_UPSTREAM_POOL_NAME=customUpstream.

    Custom domain lists

    Add 99-custom.lst and mount it into /etc/snidust/domains.d/99-custom.lst:ro — one domain per line.

    Custom nginx config

    Mount your own file at /etc/nginx/nginx.conf:ro for reverse-proxy or performance tuning.

    Reload without restarting

    SniDust answers specific magic queries and re-reads its configuration in place — no restart, no downtime.

    dig @10.111.123.8 reload.acl.snidust.local         # re-read the ACL
dig @10.111.123.8 reload.domainlist.snidust.local  # re-read the blocklists
dig @10.111.123.8 reload.certs.snidust.local       # re-read the DoT certificates

    Troubleshooting

    Port 53 already in use. On Linux, systemd-resolved (or Pi-hole) usually occupies port 53. Free it before mapping 53:5300/udp — see the guide linked from the README.

    Nothing is spoofed? Check the domain is really covered by a list (docker exec snidust cat /etc/snidust/domains.d/*.lst), that your client IP is in the ACL (docker exec snidust cat /etc/dnsdist/allowedClients.acl), and set DNSDIST_DEBUG=true to watch queries in /tmp/dnsdist.log.

    Requirements: a VPS or root server with Docker, a public IP that is not itself geo-blocked, and a client whose DNS you can change. The image is Alpine-based, runs as snidust and is supervised by tini.
